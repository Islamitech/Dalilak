# تسليم تجربة الدليل العام

## 1. الملخص التنفيذي

نسخة UI مستقلة قابلة للتكامل مع React الحالي، تشمل الاستكشاف والبحث والتصفية والمفضلة وتفاصيل النشاط والوسائط وإضافة النشاط والباقات والمساعدة. خريطة حدائق الأهرام تعرض 16 منطقة و6 بوابات من بيانات المشروع، مع أماكن افتراضية وفلاتر وسحب وتكبير وتجميع علامات على المساحات الضيقة.

مدخلها directory-preview.html ومجلدها src/directory-experience. لا تستخدم App أو خدمات Supabase ولا تستبدل واجهة الإنتاج. آخر طلب المستخدم بالاستقلال هو النطاق النهائي. [قرارات التنفيذ](decisions.md) و[تعليمات الدمج](integration.md).

## 2. خريطة المشروع

| الموضع المفحوص | علاقته بالتطبيق |
|---|---|
| package.json / vite.config.ts / tsconfig.json | React19 وTS وVite6 وTailwind4 وLucide وإعدادات البناء القائمة |
| src/main.tsx / src/App.tsx | تشغيل الإنتاج وتحميل البيانات والمزامنة؛ خارج نطاق تعديل النسخة المستقلة |
| src/components/PublicShowcase.tsx | توزيع شاشات الدليل الحالي |
| src/components: layout/views وتفاصيل النشاط والبحث والبطاقات | مرجع للتدفقات والحقول الموجودة، وليس قالبًا بصريًا للنسخة الجديدة |
| src/types.ts | نموذج Business وحقول البيانات المستخدمة في العرض |
| src/services/storage.ts وapi | حدود الخدمات الحالية؛ لا استدعاءات منها في المعاينة |
| src/data/hadayekDistrictsGeoData.ts وبيانات الأطلس والعمارات | الجغرافيا المحلية؛ أُعيد استخدام مصدر المناطق والبوابات قراءة فقط |
| الأصول المحلية | نُسخت أربع صور توضيحية إلى preview/assets لتجميعها داخل حزمة المعاينة |

المشروع يحمل تعديلات سابقة ليست لهذه المهمة؛ لا تُعامل قائمة git diff كلها بوصفها نتيجة هذا العمل. تاريخ الفحص الأول محفوظ في implementation-plan.md وموسوم بأنه خطة سابقة.

## 3. خريطة المستخدم والنطاق

| المستخدم | الهدف | التدفق |
|---|---|---|
| زائر جديد | العثور على خدمة موثوقة المعلومات | استكشاف ← تصنيف/بحث ← نتائج ← تفاصيل ← معاينة تواصل |
| ساكن حدائق الأهرام | تحديد المنطقة والبوابة والأماكن | خريطة ← منطقة/نوع نشاط ← نتيجة مرتبطة بدبوس ← تفاصيل |
| زائر عائد | مراجعة أماكنه | حفظ ← مفضلة ← تفاصيل؛ حذف الحفظ مع تراجع |
| صاحب نشاط | تقديم معلوماته ومراجعة خدمات الأعمال | إضافة نشاط ← بيانات ← مراجعة ← إرسال محاكى/خطأ ← نتيجة |
| مراجع UX | فحص الحالات والاتجاه | أدوات التجربة ← حالة الشاشة/فشل الإجراءات/RTL وLTR/نظام التصميم |

الزائر لا يحتاج حسابًا في المحاكاة. لا يُفترض دور إداري أو صلاحيات غير مثبتة. حالات عدم الصلاحية توضيحية فقط.

داخل النطاق: العرض والتفاعلات المحلية والعقود ومؤشرات الحالات. خارج النطاق: API وDB والمصادقة وCRUD والإرسال والدفع والملاحة الفعلية. الافتراضات والأسئلة البشرية مفصّلة في decisions.md.

## 5. قرارات UX/UI ونظام التصميم

- شعار public/logo.svg الرسمي، ذهب #c59b27، كحلي #0b132b، نص #0f172a وخلفية #f8fafc من الهوية الفعلية. brand.css ينسخ قيم الهوية في نطاق المعاينة؛ درجات داكنة للنص الذهبي لتحسين التباين.
- Tahoma/Arial متاحان محليًا، متن 15px وتعليقات 13px، عناوين متجاوبة. سلم مسافات 4/8/12/16/24/32/48px، زوايا 10 و18px، ظل خفيف وحدود واضحة.
- أزرار وحقول رئيسية بارتفاع 44–46px، تركيز مرئي، معطل عند غياب بيانات لازمة. النص يشرح ساعات العمل غير المتاحة بدل اعتبار النشاط مغلقًا.
- بطاقات بترتيب ثابت وتصنيفات بأيقونات Lucide. عرض قائمة للخريطة بدل جدول ضيق؛ جدول مقارنة الباقات داخل سياقها.
- تجميع الأماكن المتقاربة عند التصغير، وفصل الفلاتر عن الخريطة. طبقة البوابات اختيارية لتقليل الازدحام، واختيار بوابة يفعّلها. النقر على مجموعة يكبرها.
- نقاط التحول: الهاتف حتى 767px، تغييرات تخطيط الخريطة قرب 1000px، رأس مدمج تحت 1024px. عرض المحتوى الأقصى 1200px.
- RTL أصلي وخصائص اتجاه منطقية؛ الجغرافيا شمال لأعلى ولا تنعكس مع RTL. LTR اختبار تخطيط مع بقاء النص عربيًا.
- reduced-motion، focus-visible، تسميات الحقول، status/alert، لوحة مفاتيح للخريطة (+/-/الأسهم/Home)، Escape واستعادة التركيز للنوافذ.

راجع [قائمة الملفات ووظائفها](files.md). كل الشاشات منظمة بالمجال: discovery/map/details/owners/saved/information. العقود منفصلة عن fixtures، وحركة الخريطة منفصلة عن هندسة الإسقاط وعن الشاشة.

## 7. حدود التنفيذ

كل تواصل وإرسال ومشاركة وموقع وطلب باقة محاكاة. لا API جديد أو قاعدة بيانات أو عملية حقيقية. المفضلة والمسودات في الذاكرة وتُفقد بعد إعادة تحميل المعاينة. مشغّل الفيديو تمثيل حالات فقط. الخريطة محلية دون شوارع أو توجيه طرق، وحدودها ليست مساحية معتمدة. لا تُنسب صور العرض أو الأنشطة الوهمية إلى منشآت حقيقية.

## 8. نقاط الدمج المستقبلية

DirectoryCatalog للبيانات، DirectoryDataPort للحالات، DirectoryActions للإجراءات، عقود coordinates/districts/gates للخريطة. التطبيق المضيف يملك API/DB/auth/permissions/CRUD. ملفات المحاكاة تبقى خارج حزمة الإنتاج. التفاصيل في integration.md.

## 9. تعليمات الدمج

تشغيل المدخل المستقل، اعتماد التصميم والبيانات، بناء adapter في المضيف، إدخال المسار خلف feature flag، استبدال حالة وتنقل المحاكاة، ربط callbacks بالخدمات الموجودة، إزالة أدوات العرض، مراجعة CSS ثم الاختبارات التدريجية. [الأوامر والخطوات التفصيلية](integration.md).

## 10. قائمة التحقق

راجع [نتائج المراجعة وحدود التحقق](review-checklist.md). نجاح البناء ليس شهادة اعتماد جغرافي أو تدقيق وصولية شامل؛ تُذكر الاختبارات المنفذة وما يحتاج تحققًا إضافيًا بوضوح.
