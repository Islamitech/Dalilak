# الدليل العام — خطة التحسين قبل التنفيذ

## النطاق النهائي بعد تصحيح المستخدم
المطلوب نسخة مستقلة ومتكاملة من UX/UI تحاكي الشاشات والتدفقات، وليست تعديل التطبيق الفعلي. أُعيدت ملفات التطبيق التي تغيرت خلال المحاولة الأولى إلى نسختها الملتقطة قبل العمل. التنفيذ النهائي إضافات تحت src/directory-experience ومدخل وإعداد بناء مستقلين.

الأقسام التالية تسجل نتائج الفحص وخطة المحاولة الأولى؛ راجع delivery.md وdecisions.md للنطاق النهائي وقائمة التسليم.

## نتائج الفحص
- React 19 / TypeScript / Vite / Tailwind 4 / Lucide. main → App → PublicShowcase.
- App يحمّل البيانات المنشورة ويزامنها. أنواع Business وبيانات الأطلس والخدمات الحالية تبقى مرجعًا.
- الشاشات: الخريطة، البحث، المفضلة، تفاصيل النشاط، الصور والفيديو، الإدراج، الباقات، عن المنصة. HomeView موجود لكنه غير مستخدم في الموزع الحالي.
- الخريطة تركز فعليًا على حدائق الأهرام، بينما البحث يشمل المحافظات. يجب التصريح بهذا الفرق.
- التاريخ الحالي لا يعكس الصفحات الثانوية. إغلاق التفاصيل يفقد وجهة العودة.
- أدوات الخريطة صغيرة، والنوافذ الثانوية تحجب شريط التنقل. البطاقات مزدحمة وتعرض حالة إغلاق حتى مع ساعات غير متاحة.
- أخطاء الطلب غير معروضة. نموذج صاحب النشاط يؤكد إرسالًا لا يمكن إثباته؛ فتح WhatsApp ليس إرسالًا.
- بعض الحقول بلا تسميات مرتبطة، والنوافذ تحتاج احتجاز التركيز واستعادته وEscape.
- فحص الأنواع قبل التنفيذ ناجح. توجد تعديلات سابقة كثيرة؛ لا تراجع عنها ولا حذف لها.

## خطة العمل
1. تنقل دائم وصفحات قابلة للرجوع، مع إبقاء سياق البحث والمسودات أثناء التنقل.
2. تفعيل صفحة الاستكشاف، وإبقاء الخريطة والأطلس في /map؛ روابط zone/bldg القديمة تفتح الخريطة.
3. نظام تصميم محدود بالنطاق directory-app، ألوان حبر داكن وخلفية دافئة ولهجة ذهبية واضحة، مقاسات ومسافات مركزية.
4. إعادة تنظيم بطاقات الأنشطة والبحث والإدراج. الحفاظ على التصنيفات والباقات والاتصال والملاحة والمشاركة وحفظ جهة الاتصال.
5. تحسين تحميل/خطأ/فراغ/رفض الوصول/انقطاع الاتصال دون ابتكار صلاحيات. رفض HTTP 401/403 حالة عرض فقط.
6. مراجعة الأنواع والبناء والصفحات بالمتصفح عند أحجام هاتف ولوحي وسطح مكتب.

## نطاق الملفات المتأثرة
PublicShowcase، مكونات layout، HomeView/SearchView/FavoritesView/ForBusinessView/MapView/AboutView/BusinessPricingView، البطاقات، البحث، تفاصيل النشاط، الوسائط، نافذة البوابات وPackagesHub عند الحاجة للوصولية. مكونات مساعدة مشتركة وتنسيق جديد تحت components/directory. App: تمرير حالة الطلب وإعادة المحاولة فقط.

## ملفات مستثناة
api/*، services/storage.ts، types.ts، data/*، utils الخاصة بقواعد البيانات والتصفية والجغرافيا، إعدادات النشر وService Worker وملفات التطبيقات الشقيقة. لا تغيير حزم ولا schema ولا migration.

## القرارات والحدود
- افتراض: العربية هي اللغة الحالية؛ nameEn حقل بيانات ولا يثبت وجود واجهة مترجمة. لا إضافة ترجمة ناقصة. استخدام خصائص اتجاه منطقية في المكونات الجديدة.
- لا إعادة تفسير الأسعار أو شروط الباقات؛ مصادرها الحالية محفوظة.
- لا إرسال تجريبي إلى WhatsApp ولا اتصالات هاتفية أثناء الاختبار.
- عدم وجود ملف schema/RLS محلي يعني عدم إثبات صلاحيات المصدر من فحص الواجهة.
- مشاركة قاعدة بيانات لا تعني مشاركة ملفات الواجهة؛ package.json للتطبيق الشقيق مستقل. لن يتم تشغيله أو تعديله.
- لا تصنيف للتوثيق كضمان جودة للخدمة؛ العرض يعكس حالة المصدر فقط.
