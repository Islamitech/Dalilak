# مراجعة UX/UI — 2026-09-23

## تحقق آلي منفذ

- TypeScript: `tsc --noEmit` نجح.
- اختبارات العرض: 7/7 ناجحة. تشمل 16 منطقة و6 بوابات، هندسة finite، ثبات موضع المؤشر عند التكبير وحدوده، rendering للشاشات الأساسية، حالات الفراغ/الخطأ/التحميل/عدم الصلاحية، بيانات النشاط الناقصة، وتسميات النوافذ وصراحة المحاكاة.
- فحص مصادر النسخة: لا fetch أو XMLHttpRequest أو createClient أو geolocation/sendBeacon أو روابط واتساب تنفيذية، ولا اعتماد على App/PublicShowcase/storage.
- بناء Vite المستقل نجح: CSS نحو 41.18kB وJS نحو 302.15kB قبل الضغط، وأربع صور محلية. خرج نظيف دون sw.js أو manifest الإنتاج.

## تحقق متصفح منفذ

- سطح مكتب 1440px، لوحي 820px، هاتف 390px؛ لا overflow أفقي في القراءات التي أُجريت. راجعت الصفحة الرئيسية والخريطة والنموذج بصريًا عبر أحجام مختلفة، وليس كل تبديل حالة على كل جهاز.
- اختيار منطقة أ يغير النتائج إلى نشاط واحد. نافذة البوابات تعرض 6 بوابات، واختيار خوفو يظهر تفاصيلها ومناطق الخدمة.
- تكبير الخريطة يغير التحويل الجغرافي. اكتُشفت مشكلة rAF مع StrictMode وأُصلحت بتصفير مرجع الإطار عند cleanup.
- فتح تفاصيل مكان من الخريطة وإغلاقه بـEscape يعمل. اختيار البحث من الخريطة يعرض نتائج البحث.
- حفظ نشاط في المفضلة يحدّث العداد. نموذج النشاط يمر من البيانات إلى المراجعة ثم رسالة نجاح صريحة للمحاكاة.
- حالة error تعرض إعادة محاولة، وتبديل LTR/RTL متاح من أدوات التجربة.
- صُحّح ضيق حقل البحث في اللوحي، وصارت روابط الرأس المدمجة تمنع ازدحام التنقل.
- سجل أخطاء المتصفح عند المراجعة لم يعرض أخطاء للمعاينة.

## قائمة التسليم

| البند | النتيجة |
|---|---|
| الشاشات والتدفقات الرئيسية | منفذة؛ راجع delivery.md |
| loading / empty / error / success / offline / unauthorized | موجودة حسب سياق الشاشة؛ أدوات الشاشة العامة لقوائم البيانات، وفشل الإجراءات للنماذج والنوافذ |
| هيكل واضح حسب المجال | نعم |
| Backend/API/DB جديد | لا |
| تعديل قاعدة البيانات | لا |
| Mock Data مركزي وقابل للاستبدال | نعم عبر DirectoryCatalog |
| RTL/LTR | RTL افتراضي وLTR للتخطيط؛ لا ترجمة إنجليزية |
| تجاوب | تحقق تمثيلي على الهاتف واللوحي والكمبيوتر |
| الوصولية | تسميات وتركيز وEscape وحالات مسموعة ودعم لوحة مفاتيح؛ ليس تدقيق WCAG شاملًا |
| سهولة الدمج | مدخل مستقل وعقود وتوثيق، مع خطوات لازمة لاستبدال حالة المحاكاة وCSS العام |

## ما يحتاج مراجعة لاحقة

اختبار قارئ شاشة فعلي، وقياس أداء على هاتف حقيقي مع لمس بإصبعين، وجميع تراكيب الفلاتر بكثافة بيانات حقيقية، واعتماد التباين لجميع الحالات والأصول النهائية. لا ندعي أن اختبار المتصفح المكتبي يعادل تحقق اللمس على جهاز حقيقي. جغرافيا المناطق والبوابات تحتاج اعتماد مالك البيانات قبل النشر.
